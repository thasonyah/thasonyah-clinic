## ต้นแบบที่เพิ่ม

- /design/services: เพิ่ม แก้ชื่อ/ราคา/เวลา ค้นหา กรองสถานะ ปิดใช้งานและเปิดคืน
- กันชื่อซ้ำรวมรายการที่ปิดแล้ว; ราคาไม่ติดลบและเวลาต้องเป็นจำนวนเต็มบวก
- /design/treatment แท็บแผนการดูแล เลือกจากรายการเปิดใช้งานเดียวกัน
- รายการใช้ React state ใน DesignPreview อยู่ได้ระหว่างเปลี่ยนเมนู; รีโหลดจะกลับเป็นรายการตั้งต้น ไม่ได้บันทึกลงฐานข้อมูล
- หน้าจำลองสิทธิ์แอดมิน ยังไม่มีการตรวจสิทธิ์จริง จึงยังไม่ใช่ระบบแอดมินพร้อมใช้งาน

## ข้อกำหนดระบบจริง

1. API อ่านสำหรับผู้มีสิทธิ์ใช้งานคลินิก; POST/PATCH/ปิดใช้งาน/เปิดคืนต้องตรวจ role admin ฝั่งเซิร์ฟเวอร์ ห้ามอาศัยซ่อนปุ่ม
2. เก็บชื่อ รหัสเดิม ราคา Decimal ระยะเวลา active รุ่น เวลา ผู้แก้ และ audit log ใน PostgreSQL
3. ลบรายการด้วย soft delete; ประวัติรักษาและใบเสร็จเก็บ snapshot ชื่อ ราคา ระยะเวลา ณ วันให้บริการ ไม่เปลี่ยนตาม catalog
4. รายการปิดใช้งานเลือกลงนัด/รายการรักษาใหม่ไม่ได้ แต่ประวัติเดิมอ่านได้
5. ตรวจข้อมูลซ้ำและค่าติดลบฝั่ง API รวมคำขอพร้อมกัน; ป้องกันทับการแก้ไขด้วย version
6. ทดสอบการเพิ่ม/แก้/ปิด/คืน, 401/403, ความคงอยู่หลัง reload, การแก้ราคาไม่เปลี่ยนใบเสร็จเดิม และรายการปิดใช้ใน encounter ใหม่ไม่ได้

งานระบบจริงนี้ต่อจาก auth/permissions ตามลำดับโครงการ ยังไม่ถือว่า API หรือสิทธิ์แอดมินเสร็จ
