## ส่วนขยาย OPD — 11 กันยายน 2569

หน้า `/design/treatment` เพิ่มหมวดเปิด–ปิดภายในสามแท็บเดิม โดยคงธีมน้ำเงินคราม/ครีมและรูปแบบพื้นที่ทำงานเดิม:

- **ซักประวัติ:** ข้อมูลส่วนบุคคล การติดต่อ การเกิด และประวัติสุขภาพ
- **ตรวจและประเมิน:** สัญญาณชีพ สมุฏฐาน ตรีธาตุ 9 ช่อง พิกัดธาตุ 12 รายการ รูปธาตุ 42 รายการ และการวินิจฉัยที่ผู้รักษากรอกเอง
- **แผนการดูแล:** แผนรักษา หัตถเวชกรรม เพิ่มรายการยาตัวอย่าง สรุปผล นัดติดตาม ผู้บันทึก และสถานะความยินยอม

หมวดเริ่มต้นพับไว้และเปิดแยกกันได้ ค่าในช่องคงอยู่เมื่อสลับสามแท็บ แต่เป็น React state สำหรับสาธิตเท่านั้น เปลี่ยนคนไข้ ออกจากห้องตรวจ หรือรีโหลดแล้วค่าจะหาย ไม่มีการเชื่อมหลังบ้าน บันทึกถาวร สั่งจ่ายยา ลายเซ็น หรือหลักฐานความยินยอม ตำแหน่งปวดใช้ข้อความ ยังไม่มีผังร่างกาย และยังไม่คำนวณ BMI อายุ วันเกิดจันทรคติ หรือจักรราศี

ดูแหล่งที่มาและสถานะรายหมวดใน [OPD reference mapping](../04-opd-reference-mapping.md) ผลตรวจเดิมด้านบนเป็นของต้นแบบก่อนส่วนขยายนี้ ไม่ใช่ผลรับรอง OPD รอบใหม่

## ส่วนขยายรายการหัตถการ — 11 กันยายน 2569

หน้า `/design/services` คงธีมน้ำเงินคราม/ครีมเดิม และจำลองงานแอดมินสำหรับเพิ่ม แก้ชื่อ/ราคา/เวลา ค้นหา กรองสถานะ ปิดใช้งาน และเปิดคืน รายการตั้งต้น 12 รายการพร้อมราคาและเวลามาจากหน้าบริการคลินิกตาม [แหล่งข้อมูลและข้อกำหนด](../05-service-catalog.md) เป็น snapshot ไม่ใช่การซิงก์สด แถบต้นแบบจึงระบุ “คนไข้สมมติ” แทนการเรียกข้อมูลทั้งหมดว่าสมมติ

แท็บแผนการดูแลในห้องตรวจใช้รายการเดียวกัน เลือกหัตถการที่เปิดใช้งานได้ ฟอร์มกันชื่อซ้ำรวมรายการปิดใช้งาน ราคาไม่ติดลบ และเวลาต้องเป็นจำนวนเต็มบวก การแก้ catalog คงอยู่เมื่อเปลี่ยนเมนูด้วย React state แต่รีโหลดแล้วกลับเป็นรายการตั้งต้น ยังไม่มี backend, auth, การตรวจสิทธิ์แอดมิน หรือบันทึกถาวร ผลตรวจเดิมด้านบนไม่ใช่ผลรับรองส่วนขยายนี้

## ยังเหลือ

การเลือกธีมนี้ไม่ใช่การทำ auth หรือฟีเจอร์หลังบ้านเสร็จ ขั้นที่ 3 ยังรอการเชื่อม GitHub บัญชี thasonyah และชื่อ repo; หลังปิดขั้นที่ 3 ยังเหลือขั้นที่ 4–8 ตามแผนเดิม


## ทะเบียนและบันทึกถาวรระยะแรก — 12 กันยายน 2569

หน้า `/staff` ใน `Records.jsx` และ `Workspace.jsx` เพิ่มงานจริงสำหรับคลินิกสาขาเดียว โดยคงธีมน้ำเงินคราม/ครีมและพื้นที่ทำงานแบบ Operate เดิม Reception ลงทะเบียนชื่อ วันเกิด โทรศัพท์ และผู้รักษาที่รับผิดชอบหนึ่งคน; practitioner ค้นและเปิดคนไข้ที่ได้รับมอบหมาย สร้างร่างอาการสำคัญกับผลตรวจ/แผนการดูแลแบบข้อความอิสระลง API และฐานข้อมูลถาวร แล้วตรวจทานก่อนกดยืนยันอีกครั้งเพื่อป้องกันแก้ทับฉบับยืนยัน การยืนยันนี้ผ่านบัญชีผู้ใช้ ไม่ใช่ลายเซ็นดิจิทัลตามใบรับรอง

เพิ่มข้อความเตือนข้อมูลยังไม่บันทึกและปุ่มละทิ้ง พร้อมปิดการเปลี่ยนคนไข้ เมนู และออกจากระบบขณะมีข้อความค้าง; browser เตือนก่อนรีโหลด/ปิดหน้าที่มีข้อมูลค้างด้วย ขณะส่งคำขอปิดการเปลี่ยนบริบท ไม่ใช่การบันทึกอัตโนมัติ

สถานะนี้ใช้กับ `/staff` เท่านั้น; `/design/*` ยังเป็นต้นแบบเดิม ช่อง OPD แบบโครงสร้างยังไม่เชื่อมบันทึกถาวร และยังไม่มีการแก้ร่างผ่าน UI, amendment, audit log หรือ export จึงยังไม่ใช่ระบบ production ที่เสร็จสมบูรณ์ ดูหลักฐานและงานคงเหลือใน [ความคืบหน้าทะเบียน](../09-records-progress.md); ผลตรวจต้นแบบด้านบนไม่ใช่การรับรองส่วนขยายนี้

## ลืมรหัสผ่านและตั้งรหัสผ่านใหม่ — 13 กันยายน 2569

หน้า `/staff` เพิ่มฟอร์มขอลิงก์รีเซ็ตด้วยอีเมล และฟอร์มตั้งรหัสผ่านใหม่พร้อมช่องยืนยันเมื่อเปิดลิงก์รีเซ็ต โดยใช้แผงฟอร์ม ปุ่ม และข้อความสถานะในธีมน้ำเงินคราม/ครีมแบบ Operate เดิม มีปุ่มกลับไปเข้าสู่ระบบและขอลิงก์ใหม่ พร้อมปิดปุ่มระหว่างส่งคำขอ

หน้าจอแจ้งว่าลิงก์มีอายุ 15 นาทีและใช้ได้ครั้งเดียว รหัสใหม่ต้องตรงกันทั้งสองช่อง อย่างน้อย 12 ตัวอักษรและไม่เกิน 72 ไบต์ หลังเปลี่ยนสำเร็จต้องเข้าสู่ระบบใหม่ทุกอุปกรณ์ หากยังไม่ตั้งค่าระบบส่งอีเมล จะแสดงข้อความว่าระบบยังไม่พร้อม ไม่แสดงว่าส่งแล้ว

ยังไม่ได้ทดสอบส่งและรับอีเมลจริง ต้องตั้งค่าผู้ให้บริการส่งอีเมลก่อนใช้งาน ดูรายละเอียดและหลักฐานทดสอบใน [การรีเซ็ตทางอีเมล](../10-password-recovery.md); ผลตรวจต้นแบบด้านบนไม่ใช่การรับรอง UI ส่วนนี้
