# ข้อกำหนดระบบบริหารคลินิกแพทย์แผนไทย — ขั้นที่ 1

วันที่: 2026-09-10 | เวอร์ชัน: 0.1 | สถานะ: ผู้ใช้ให้ดำเนินการขั้นที่ 2 ต่อ; รายละเอียดที่ระบุรอยืนยันยังคงเปิดอยู่
ชื่อผลิตภัณฑ์/ชื่อ repository: รอยืนยัน (ThaiClinic Care เป็นเพียงชื่อเสนอ)

## 1. เป้าหมายและสถานะข้อตกลง

ผู้ใช้ยืนยันขอบเขต Full Function ตามการสนทนาและเลือก Render.com แล้ว เอกสารนี้จัดรายละเอียดเป็น FR/NFR, user stories, acceptance criteria และแผนส่งมอบเพื่ออนุมัติขั้นที่ 1 ยังไม่ใช่การอนุมัติแบบฐานข้อมูลหรือเริ่มพัฒนา

เป้าหมาย: เชื่อมทะเบียน นัดหมาย ตรวจรักษาแพทย์แผนไทย จ่ายสมุนไพร รับเงิน และติดตามผลเข้าด้วยกัน พร้อมงานบริหารคลินิก ลดข้อมูลซ้ำและตรวจสอบรายการย้อนหลังได้ ไม่กำหนดตัวเลขผลลัพธ์ทางธุรกิจหรือผลการรักษาที่ไม่มีข้อมูลฐานรองรับ

กระบวนการหลัก: ลงทะเบียน → นัดหมาย/Walk-in → เช็กอิน → ตรวจและวินิจฉัยโดยผู้รักษา → หัตถการ/จ่ายยา → รับชำระ → นัดติดตาม

## 2. ผู้เกี่ยวข้องและสิทธิ์ที่เสนอ

| บทบาท | ขอบเขต |
|---|---|
| เจ้าของ/ผู้จัดการ | รายงาน ตั้งค่า และอนุมัติรายการตามวงเงินที่กำหนด |
| ผู้ดูแลระบบ | บัญชีและสิทธิ์ ไม่มีสิทธิ์อ่านเวชระเบียนโดยอัตโนมัติ |
| แพทย์แผนไทย/ผู้รักษา | ข้อมูลทางคลินิกที่ได้รับมอบหมาย ตรวจ วินิจฉัย ยืนยันคำสั่งและบันทึก |
| เจ้าหน้าที่ต้อนรับ | ทะเบียน นัดหมาย คิว ข้อมูลเตือนที่จำเป็น ไม่แก้บันทึกการรักษา |
| เจ้าหน้าที่การเงิน | ค่าบริการ รับชำระ ใบเสร็จ ไม่เปิดเวชระเบียนทั้งหมด |
| เจ้าหน้าที่คลัง/ผู้จ่ายยา | คลังและคำสั่งจ่ายที่จำเป็นตามสิทธิ์และคุณสมบัติ |
| คนไข้/ผู้ดูแล | เฉพาะข้อมูลของตนหรือข้อมูลที่ได้รับมอบสิทธิ์อย่างชัดเจน |

หนึ่งบุคคลมีหลายบทบาทได้ แต่ต้องมอบสิทธิ์ชัดเจน การเข้าถึงข้ามสาขาและข้อมูลคนไข้ต้องตรวจฝั่ง API ทุกครั้ง ตารางสิทธิ์ระดับการกระทำจะจัดทำในขั้นออกแบบ

## 3. FR + User stories + Acceptance criteria

แต่ละแถวเป็น epic ที่ต้องแตกกรณีทดสอบย่อยก่อนลงมือทำ หลักฐานทุกชุดต้องอ้าง FR และ AC กลับมาได้ P1–P4 คือระยะส่งมอบ ไม่ใช่การตัดฟีเจอร์ออก

| FR / เฟส | User story และความสามารถ | Acceptance criteria |
|---|---|---|
| FR-01 / P1 | ผู้ดูแลจัดการผู้ใช้ บทบาท เข้าสู่ระบบ ออกจากระบบ และระงับบัญชี | AC-01: ไม่ล็อกอินได้ 401; ล็อกอินแต่ไร้สิทธิ์ได้ 403; ระงับบัญชีแล้วใช้ API ที่ป้องกันไม่ได้; ผู้ดูแลที่ไม่มีสิทธิ์รักษาอ่านเวชระเบียนไม่ได้ |
| FR-02 / P1 | ผู้จัดการตั้งคลินิก บริการ ราคา ห้อง เตียง ระยะเวลาและเวลาเตรียมห้อง | AC-02: ทรัพยากรปิดใช้งานไม่รับนัดใหม่; แก้ราคาบริการไม่เปลี่ยนรายการที่ออกเอกสารแล้ว |
| FR-03 / P1 | เจ้าหน้าที่ลงทะเบียน ค้นหาคนไข้ ประวัติสุขภาพ แพ้ยา ผู้ติดต่อฉุกเฉินและผู้ดูแล | AC-03: ค้นตามรหัส ชื่อ เบอร์โทรได้เฉพาะผู้มีสิทธิ์; วันเกิดไม่ทราบเก็บเป็นไม่ทราบ; แยกไม่แพ้ยาจากยังไม่ประเมิน |
| FR-04 / P2 | เจ้าหน้าที่ตรวจและรวมทะเบียนซ้ำ | AC-04: แสดงรายการที่จะรวมก่อนยืนยัน; ประวัติรับบริการไม่สูญหาย; เก็บรหัสเดิม ผู้อนุมัติ และหลักฐานการรวม |
| FR-05 / P1 | เจ้าหน้าที่จอง เลื่อน ยกเลิกนัด และจัดผู้รักษา/ห้อง/เตียง | AC-05: แย่งช่องสุดท้าย 10 เธรดสำเร็จหนึ่งรายการ; นัดระยะเวลาต่างกันห้ามทับซ้อน; เลื่อนล้มเหลวต้องคงนัดเดิม; ยกเลิกคืนทรัพยากรทั้งหมด |
| FR-06 / P1 | เจ้าหน้าที่รับ Walk-in เช็กอิน เรียกคิวและเปลี่ยนสถานะ | AC-06: ไม่ข้ามสถานะที่ไม่อนุญาต; เรียกคิวพร้อมกันไม่รับเคสซ้ำ; จอสาธารณะแสดงเพียงรหัสคิวที่ไม่เปิดเผยชื่อหรือสุขภาพ |
| FR-07 / P1 | ผู้รักษาซักประวัติอาหาร นอน ขับถ่าย อิริยาบถ อารมณ์และตรวจร่างกาย | AC-07: บันทึกอาการ สัญญาณชีพ ผลตรวจ ผู้ตรวจและเวลา; แยกคำบอกเล่าจากผลตรวจ; แบบฟอร์มมีเวอร์ชัน |
| FR-08 / P1 | ผู้รักษาประเมินธาตุเจ้าเรือน ธาตุทั้ง 4 และสมุฏฐาน | AC-08: เก็บวิธี/ตำรา อาการสนับสนุนและผลประเมิน; ธาตุกำเนิดแยกจากผลประเมินปัจจุบัน; ไม่ยืนยันข้อวินิจฉัยแทนผู้รักษา |
| FR-09 / P1 | ระบบบันทึกจักรราศีสมุฏฐานจากวันเกิดอัตโนมัติโดยไม่ถามราศีคนไข้ | AC-09: ใช้กฎและปฏิทินตามเอกสารผู้ใช้ที่ตรวจแล้ว; เก็บราศี ธาตุ ภาวะตามตำรา สมุฏฐานระคน วันเกิดที่ใช้และเวอร์ชันกฎ; วันเกิดไม่ครบ/นอกช่วงให้สถานะคำนวณไม่ได้; แก้วันเกิดคำนวณใหม่แต่เก็บผลในบันทึกเดิม; ทดสอบขึ้นแรม รอยต่อ เดือนอธิกมาสและ พ.ศ./ค.ศ.; ห้ามใช้ตารางราศีทั่วไปแทนโดยพลการ |
| FR-10 / P1 | ผู้รักษาบันทึกวินิจฉัย แผนรักษาและแผนภาพร่างกาย | AC-10: ระบุข้อวินิจฉัยเบื้องต้น/ยืนยัน เหตุผล เป้าหมาย ตำแหน่งและบริการ; แผนภาพเส้น/จุดอ้างตำราที่เลือก; คนไม่มีสิทธิ์ยืนยันคำสั่งไม่ได้ |
| FR-11 / P1 | ผู้รักษาบันทึกหัตถการและผลก่อน–หลัง | AC-11: เก็บผู้ทำ ตำแหน่ง เทคนิค ระยะเวลา ประเมินก่อนทำและผลหลังทำ; จำกัดบริการตามผู้ปฏิบัติและทรัพยากร |
| FR-12 / P1 | ผู้รักษาปิดบันทึกและแก้ไขเพิ่มเติม | AC-12: บันทึกยืนยันแล้วไม่เขียนทับ; เพิ่มฉบับแก้พร้อมเหตุผล ผู้แก้ เวลา และอ่านต้นฉบับได้ |
| FR-13 / P1 | ผู้รักษาติดตามอาการ การใช้ชีวิต ส่งต่อและเหตุไม่พึงประสงค์ | AC-13: คะแนนศูนย์แยกจากไม่มีผลประเมิน; เปรียบเทียบเครื่องมือประเมินชนิดเดียวกัน; เหตุมีผู้รับผิดชอบ สถานะและผลติดตาม |
| FR-14 / P1 | ผู้รักษาสั่งยา ผู้จ่ายตรวจและจ่ายสมุนไพร | AC-14: เก็บรายการ วิธีใช้ ฉลาก ผู้สั่ง/ผู้จ่ายและล็อต; จ่ายบางส่วนได้; แสดงแพ้ยา/ยาที่ใช้อยู่; การไม่มีข้อมูลปฏิกิริยาระหว่างยาไม่แสดงว่าไม่มีความเสี่ยง |
| FR-15 / P1 | เจ้าหน้าที่คลังรับเข้า เบิก คืน ตรวจนับและจัดการล็อต | AC-15: หน่วยซื้อ–เก็บ–จ่ายแปลงถูกต้อง; ล็อตระงับ/หมดอายุจ่ายไม่ได้; แย่งสินค้าชิ้นสุดท้าย 10 เธรดสำเร็จหนึ่ง; ยอดไม่ติดลบ; การคืนไม่เพิ่มสต็อกขายได้อัตโนมัติก่อนตรวจ |
| FR-16 / P2 | เจ้าหน้าที่จัดซื้อและเรียกคืนสมุนไพร | AC-16: ใบสั่งซื้อเชื่อมรับเข้าบางส่วนและผู้จำหน่าย; ค้นผู้รับยาตามล็อต ระงับล็อต และติดตามการติดต่อได้ |
| FR-17 / P2 | ผู้ปรุงจัดสูตรเฉพาะรายและรุ่นผลิต | AC-17: เก็บเวอร์ชันสูตร ปริมาณ วัตถุดิบและล็อต ผู้สั่ง ผู้ปรุง ผู้ตรวจ ผลผลิต/ของเสีย; สืบย้อนวัตถุดิบได้; รายละเอียดกระบวนการผลิตต้องยืนยันกับคลินิก |
| FR-18 / P1 | การเงินคิดค่าบริการ รับมัดจำ ชำระบางส่วน/หลายช่องทางและออกใบเสร็จ | AC-18: จำนวนเงินใช้ทศนิยมที่แน่นอน; ส่งคำขอเดิมซ้ำไม่รับเงินซ้ำ; ยอดขาย เงินมัดจำ รับจริงและค้างชำระแยกชัด; ใบเสร็จมีเลขไม่ซ้ำ |
| FR-19 / P1 | การเงินคืนเงิน ยกเลิกเอกสารและปิดยอด | AC-19: คืนไม่เกินยอดที่คืนได้; เก็บเหตุผลและผู้อนุมัติ; กระทบยอดตามช่องทางพร้อมส่วนต่าง; รายการเดิมไม่ถูกลบ |
| FR-20 / P2 | เจ้าหน้าที่ขายคอร์ส สมาชิก พัก/หมดอายุและคืนสิทธิ์ | AC-20: แย่งสิทธิ์ครั้งสุดท้าย 10 เธรดสำเร็จหนึ่ง; ตัดซ้ำไม่ได้; คืนเงิน/คืนสิทธิ์ใช้กฎที่อนุมัติและมีประวัติ |
| FR-21 / P2 | คนไข้จองออนไลน์ เข้าหน้าส่วนตัวและใช้สิทธิ์ผู้ดูแล | AC-21: อ่านได้เฉพาะข้อมูลที่ตนมีสิทธิ์; เปลี่ยนรหัสคนไข้ใน URL ไม่อ่านข้อมูลผู้อื่น; หน้าสาธารณะไม่คืน PII; ผู้ดูแลต้องมีหลักฐานมอบสิทธิ์ |
| FR-22 / P2 | เจ้าหน้าที่ใช้ LINE/อีเมล เตือนนัดและรายชื่อรอคิว | AC-22: เก็บสถานะส่งและ retry ไม่ซ้ำ; เคารพสิทธิ์ติดต่อ; คนยกเลิกนัดไม่รับข้อความเตือนนัดเก่า; ไม่ใส่เวชระเบียนในข้อความแจ้งเตือน |
| FR-23 / P1–P2 | ผู้รักษาใช้เอกสารยินยอม คำแนะนำและแบบฟอร์มเฉพาะกลุ่ม | AC-23: เก็บฉบับที่ลงนาม เวลา ผู้ลงนามและผู้ตรวจ; แม่แบบใหม่ไม่เปลี่ยนเอกสารเก่า; คำแนะนำมีผู้รักษายืนยัน; P1 เอกสารหลัก P2 ลงนาม/กรอกทางไกล |
| FR-24 / P2 | เจ้าหน้าที่จัดการติดตาม ความพึงพอใจ ข้อร้องเรียน งานโทรกลับและแคมเปญ | AC-24: มีเจ้าของงาน วันครบกำหนด สถานะและประวัติ; แคมเปญส่งเฉพาะผู้มีสิทธิ์ติดต่อและยกเลิกรับได้ |
| FR-25 / P3 | ผู้จัดการบริหารเวร วันลา คุณสมบัติและค่าตอบแทน | AC-25: วันลาที่อนุมัติแสดงนัดที่ได้รับผลกระทบ ไม่ยกเลิกเงียบ; สูตรค่าตอบแทนมีเวอร์ชัน; คืนเงินสะท้อนรายการปรับค่าตอบแทน |
| FR-26 / P1–P3 | เจ้าหน้าที่ดูแลห้อง อุปกรณ์และงานภายใน | AC-26: P1 ปิดทรัพยากรไม่พร้อมได้; P3 มีรอบทำความสะอาด/บำรุงและหลักฐาน; ตรวจงานที่กระทบการจอง |
| FR-27 / P3 | เจ้าของบริหารต้นทุน ค่าใช้จ่าย เจ้าหนี้และส่งออกบัญชี | AC-27: รายงานย้อนถึงรายการต้นทาง; แยกรับเงินจริงจากรายได้/ต้นทุน; รูปแบบส่งออกผ่านการตกลงกับผู้ใช้บัญชี |
| FR-28 / P1–P3 | เจ้าของดูรายงานและควบคุมหลายสาขา | AC-28: P1 ผู้รับบริการ รายรับสุทธิ ขาดนัดและสต็อกตรงรายการ; P3 เพิ่มเวลารอ เตียง ต้นทุนและเทียบสาขา; การโอนคลังมีรับ–ส่ง; ผู้ไร้สิทธิ์ข้ามสาขาไม่ได้ |
| FR-29 / P1–P2 | ผู้ดูแลนำเข้า ส่งออกและจัดการคำขอข้อมูล | AC-29: P1 audit/สำรองและส่งออกจำกัดสิทธิ์; P2 นำเข้ามี preview ข้อผิดพลาดรายแถวและตรวจซ้ำ; คำขอลบ/แก้มีขั้นตรวจข้อกำหนดการเก็บรักษาก่อนดำเนินการ |

## 5. เกณฑ์จบ P1

1. ผู้ใช้แต่ละบทบาททำงานตั้งแต่ทะเบียนจนติดตามผลครบ พร้อมทดสอบผู้ไร้สิทธิ์
2. นัด/เตียง ยา และรับเงินไม่ซ้ำหรือติดลบเมื่อยิงพร้อมกันหรือ retry; ตรวจ rollback ด้วย
3. คำนวณจักรราศีจากกฎที่ผู้ใช้ตรวจยืนยันแล้ว พร้อม fixture วันรอยต่อ ไม่ใช้การเดากฎ
4. บันทึกยืนยันแล้วมีประวัติแก้ไข เอกสารเงินและรายงานกระทบยอดได้
5. CI ผ่านทั้งสอง job; มีหลักฐาน red/green; ทดสอบ migration จากฐานว่างและอัปเกรด
6. Render staging/demo ทำงานครบโดยข้อมูลสมมติ พร้อมหลักฐาน smoke test และกู้คืน
7. การใช้กับคนไข้จริงต้องตรวจ readiness ด้านสิทธิ์ เอกสาร การเก็บข้อมูลและการปฏิบัติงานก่อน ไม่ถือว่า demo คือ production พร้อมใช้

## 6. แผนส่งมอบ

- P1: งานหลักหนึ่งสาขา + เวชกรรมไทย/จักรราศี + สมุนไพร/คลังพื้นฐาน + การเงิน + audit/กู้คืน
- P2: จองและแบบฟอร์มออนไลน์ LINE/CRM คอร์ส จัดซื้อ/ปรุงยา คลังตำราและงานติดตาม
- P3: บุคลากร ต้นทุน หลายสาขา อุปกรณ์ และการเชื่อมเคลม/แล็บที่ยืนยันแล้ว
- P4: AI และการสรุปข้อมูลขั้นสูง พร้อมการประเมินและขั้นผู้รักษายืนยัน

ทุกเฟสคงกระบวนการ 8 ขั้นของผู้ใช้: ขั้น 1 ข้อกำหนด → 2 ER/API/สถาปัตยกรรม → 3 scaffold/CI/GitHub → 4 auth → 5 ฟีเจอร์ผ่าน PR → 6 seed/UI → 7 Render/production test → 8 เอกสารฉบับส่งมอบ เอกสารและ tests ปรับต่อเนื่องระหว่างพัฒนา ไม่รอขั้นสุดท้าย

| LINE OA/payment/email/AI/แล็บ/เคลมที่ใช้จริง | แต่ละ integration; ไม่ถือว่าพร้อมใช้งานจนทดสอบปลายทาง |
