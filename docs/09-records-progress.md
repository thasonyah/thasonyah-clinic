## ข้อจำกัดและลำดับที่ยังต้องต่อ

ยังไม่ใช่ระบบ Full Function ที่เสร็จทั้งโครงการ:

1. OPD แบบโครงสร้างทุกช่องจาก PDF/รูปธาตุ 42, ผังร่างกาย, แพ้ยาและสัญญาณชีพ, แก้ร่างผ่าน UI, amendment ของฉบับยืนยัน, audit log และ export
2. ทะเบียนที่อยู่/ข้อมูลติดต่อเต็ม, แก้/ค้นหาเพิ่มเติม, หลายสาขา, การเปลี่ยนผู้รักษา/มอบหมายหลายคน
3. นัดหมาย คิว เตียง และทรัพยากรพร้อม concurrency; ปัจจุบันหน้าดีไซน์ยังสมมติ
4. ใบสั่งยา คลังล็อต/หมดอายุและการจ่ายยา, การเงิน/ใบเสร็จ/คืนเงิน และรายงาน
5. จักรราศี: mapping มีแล้ว ต้องยืนยันกฎจันทรคติและกรณีอธิกมาสก่อนคำนวณ
6. หน้าจัดการบัญชี/เปลี่ยนรหัสผ่าน, สิทธิ์ละเอียด, last-admin guard และ audit
7. GitHub repository/PR/CI/branch protection, Render, acceptance เต็มระบบ, backup/restore และเอกสารส่งมอบ

ขอบเขตปัจจุบันคลินิกสาขาเดียว; provider_id ที่ทะเบียนเป็นผู้รับผิดชอบเพียงคนเดียว ใช้ข้อจำกัดนี้เพื่อไม่เปิดข้อมูลให้ผู้รักษาทุกคนโดยพลการ
ข้อมูลทดสอบทั้งหมดอยู่ฐาน clinic_auth_test; frontend QA port 5174/API8001 แยกจาก local runtime5173/8000 ไม่ใช่ production

## ตรวจหน้าจอรอบสุดท้าย

ผู้ตรวจอิสระรับรอง initial flow หลังแก้การป้องกันข้อมูลร่างสูญหายเมื่อเปลี่ยนคนไข้/เมนู และข้อความ error ให้ตรงกับทะเบียน/การตรวจ การ reload เตือนเมื่อมีข้อความที่ยังไม่บันทึก ผู้ใช้บันทึกหรือละทิ้งเองได้ ไม่ใช่การรับรอง readiness ทั้งระบบ
