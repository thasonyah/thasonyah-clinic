# คู่มือใช้งานระบบคลินิกธสัญญา — ฉบับส่งมอบเบื้องต้น

วันที่อัปเดต: 27 กันยายน 2026

ระบบ production:

- หน้าเว็บคลินิก: https://clinic-web-3z3c.onrender.com/
- ระบบเจ้าหน้าที่: https://clinic-web-3z3c.onrender.com/staff
- Backend readiness: https://clinic-api-rl26.onrender.com/api/v1/readyz

คู่มือนี้ใช้สำหรับตรวจรับและเริ่มสอนงานเจ้าหน้าที่ ยังไม่ใช่นโยบายเวชระเบียนฉบับสุดท้ายของคลินิก

## 1. บทบาทผู้ใช้

### Admin

ใช้สำหรับจัดการบัญชีและสิทธิ์หลักของระบบ

งานหลัก:

1. สร้างบัญชีเจ้าหน้าที่
2. กำหนดบทบาท เช่น reception, practitioner, admin
3. ปิดบัญชีที่ไม่ได้ใช้งาน
4. ตรวจว่าผู้ใช้แต่ละคนมีสิทธิ์เท่าที่จำเป็นกับงาน

ข้อควรระวัง:

- ไม่ควรใช้บัญชี admin ทำงานตรวจรักษาประจำวัน
- ไม่ส่งรหัสผ่านผ่านแชตหรือเอกสารเปิดเผย
- หากลืมรหัส ใช้เมนูรีเซ็ตทางอีเมลเมื่อระบบส่งอีเมลพร้อมแล้ว

### Reception

ใช้สำหรับรับคำขอจอง ลงทะเบียนคนไข้ และจัดคิว

งานหลัก:

1. เปิด `/staff` และเข้าสู่ระบบ
2. ตรวจรายการคำขอจองจากหน้าเว็บ
3. เลือกผู้รักษาและทรัพยากรที่เหมาะสม
4. กด “สร้างนัดจากคำขอ” เพื่อสร้างคนไข้และนัดหมายจริง
5. ลงทะเบียนคนไข้ใหม่เมื่อมาหน้าคลินิก
6. ตรวจตารางนัดและสถานะการเข้ารับบริการ

ข้อควรระวัง:

- ตรวจชื่อ เบอร์โทร วันเวลา และบริการก่อนยืนยันคำขอจอง
- หากเป็นข้อมูลทดสอบ ให้ระบุในชื่อหรือหมายเหตุว่าเป็น TEST และลบ/ยกเลิกหลังตรวจรับ
- ไม่สร้างคำขอซ้ำหากระบบแสดงสถานะ “นัดหมายแล้ว”

### Practitioner

ใช้สำหรับเปิดแฟ้มคนไข้ บันทึกการตรวจ และวางแผนการดูแล

งานหลัก:

1. เปิดแฟ้มคนไข้ที่ได้รับมอบหมาย
2. ตรวจข้อมูลพื้นฐาน วันเกิด เบอร์โทร และประวัติสำคัญ
3. บันทึกอาการสำคัญ ผลตรวจ การวินิจฉัย และแผนดูแล
4. ตรวจข้อมูลแพทย์แผนไทย เช่น จักรราศี/ธาตุ ที่ระบบช่วยคำนวณจากวันเกิด
5. ตรวจทานร่างก่อนยืนยันบันทึก

ข้อควรระวัง:

- ผลจันทรคติ/จักรราศีเป็นข้อมูลประกอบ ต้องตรวจรับกฎอธิกมาส/อธิกวารก่อนใช้เป็นข้อมูลจริงเต็มรูปแบบ
- อย่าปิดหน้าเมื่อมีข้อความแจ้งว่ามีข้อมูลยังไม่บันทึก
- การยืนยันบันทึกเป็นการยืนยันโดยบัญชีผู้ใช้ ยังไม่ใช่ลายเซ็นดิจิทัลตามกฎหมาย

### Pharmacy / Stock

ใช้สำหรับจัดการรายการยา ล็อต วันหมดอายุ และการจ่ายยา

งานหลัก:

1. ตรวจล็อตคงเหลือก่อนจ่าย
2. เลือกลอตที่ถูกต้องตามวันหมดอายุและจำนวนคงเหลือ
3. บันทึกการจ่ายบางส่วนหรือจ่ายครบตามใบสั่ง
4. ตรวจนับและปรับสต็อกเมื่อมีเหตุผลรองรับ

ข้อควรระวัง:

- ไม่จ่ายเกินจำนวนในใบสั่งหรือเกินล็อตคงเหลือ
- บันทึกเหตุผลทุกครั้งเมื่อปรับสต็อก

### Billing / Cashier

ใช้สำหรับรับเงิน ออกใบรับเงิน คืนเงิน และปิดยอดเงินสด

งานหลัก:

1. เปิดรายการค่าใช้จ่ายของ visit/บริการ
2. รับชำระเต็มจำนวนหรือบางส่วน
3. ออกใบรับเงิน
4. บันทึกคืนเงินเมื่อจำเป็น
5. ปิดยอดเงินสดตามรอบงาน

ข้อควรระวัง:

- ตรวจยอดก่อนออกใบรับเงิน
- ไม่แก้ยอดย้อนหลังโดยไม่มีบันทึกเหตุผล
- ปิดยอดเงินสดตามรอบที่คลินิกกำหนด

## 2. Flow ตรวจรับ production smoke test

ก่อนเปิดใช้จริง ควรทดสอบด้วยข้อมูลสมมติ 1 ชุดตามลำดับนี้:

1. เปิดหน้าเว็บคลินิกและส่งคำขอจองด้วยชื่อที่มีคำว่า `TEST`
2. เข้าระบบด้วยบัญชี reception
3. เปิดคำขอจอง เลือกผู้รักษา แล้วสร้างนัดจากคำขอ
4. เปิดแฟ้มคนไข้ที่สร้างขึ้น ตรวจว่าข้อมูลชื่อ/เบอร์/วันนัดถูกต้อง
5. เข้าด้วย practitioner แล้วบันทึก OPD แบบสั้น
6. เพิ่มบริการหรือรายการดูแล
7. ทดสอบรับเงินบางส่วนหรือเต็มจำนวนด้วยยอดเล็ก
8. ตรวจใบรับเงินและประวัติธุรกรรม
9. ยกเลิก/ทำเครื่องหมายข้อมูล TEST ตามนโยบายคลินิก
10. บันทึกผลตรวจรับพร้อมวันเวลาและผู้ตรวจ

ห้ามใช้ข้อมูลคนไข้จริงในรอบ smoke test จนกว่าจะปิดรายการ readiness ทั้งหมด

## 3. การลืมรหัสผ่าน

1. เปิด `/staff`
2. เลือก “ลืมรหัสผ่าน”
3. กรอกอีเมลที่ผูกกับบัญชี
4. เปิดอีเมลรีเซ็ตและตั้งรหัสใหม่
5. เข้าสู่ระบบใหม่ทุกอุปกรณ์

ข้อกำหนดรหัสผ่านใหม่:

- อย่างน้อย 12 ตัวอักษร
- ไม่เกิน 72 ไบต์
- ลิงก์รีเซ็ตมีอายุจำกัดและใช้ได้ครั้งเดียว

หากระบบแจ้งว่ายังไม่พร้อมส่งอีเมล ให้ตรวจค่า `RESEND_API_KEY` และ `RESET_EMAIL_FROM` ใน Render Environment

## 4. การตรวจสุขภาพระบบ

ตรวจแบบเร็ว:

1. เปิด https://clinic-api-rl26.onrender.com/api/v1/readyz
2. ควรเห็น `{"status":"ready"}`
3. เปิด https://clinic-web-3z3c.onrender.com/
4. ตรวจปุ่มจองคิว ข้อมูลติดต่อ และลิงก์ LINE/แผนที่
5. เปิด `/staff` และตรวจหน้าเข้าสู่ระบบ

หาก API ไม่ตอบสนอง อาจเป็น cold start ของ Render ให้รอประมาณ 30–60 วินาทีแล้วลองอีกครั้ง หากยังไม่กลับมา ให้ตรวจ Render deploy/logs

## 5. รายการที่ต้องกำหนดโดยเจ้าของคลินิก

ก่อนเปิดใช้จริง เจ้าของคลินิกควรกำหนดเป็นลายลักษณ์อักษร:

1. รายชื่อผู้ใช้จริงและบทบาทของแต่ละคน
2. วิธีจัดการข้อมูลทดสอบหลังตรวจรับ
3. รอบการสำรองข้อมูลและผู้รับผิดชอบตรวจ restore
4. นโยบายเก็บรักษาเอกสารยินยอม ใบเสร็จ และเวชระเบียน
5. ผู้อนุมัติการแก้ไขข้อมูลย้อนหลัง
6. วิธีติดต่อเมื่อระบบล่ม เช่น เบอร์/LINE เจ้าหน้าที่รับผิดชอบ

## 6. ข้อจำกัดที่ต้องแจ้งผู้ใช้งาน

- จักรราศี/ธาตุอัตโนมัติยังต้องตรวจรับเคสอธิกมาส/อธิกวารเพิ่มเติมก่อนใช้เป็นหลักฐานทางคลินิกเต็มรูปแบบ
- Production smoke test ยังไม่ควรใช้ข้อมูลคนไข้จริง
- ระบบยังต้องตั้งนโยบาย backup/restore production ให้ชัดเจนก่อนเปิดใช้งานเต็มรูปแบบ
- การยืนยันบันทึกในระบบเป็น audit โดยบัญชีผู้ใช้ ยังไม่ใช่ระบบลายเซ็นดิจิทัลภายนอก
